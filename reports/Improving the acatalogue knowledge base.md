# Fix silent losses before scaling acatalogue

acatalogue's foundations are already right. SHA-512 exact-byte sources, never-delete triggers, bitemporal claims, a hash-chained ledger, sealed dated corpora and an epistemic vocabulary richer than Wikidata's ranks match what Wikidata, DBpedia and nanopublications settled on. So the most urgent improvements are not new features. They repair six boundaries where the implementation quietly drops, relabels or misses data. The claim importer reads WDQS query results rather than entity JSON, so all **4,045 claims** trace to three files that contain no statement IDs (GUIDs), qualifiers, references, snak types or revision numbers. Its identity key will silently discard the second of two statements that differ only in qualifiers. It skips every value that is not a Wikidata item, labels all **81 deprecated claims** "superseded", and uses a corpus-wide supersession rule that would retire untouched claims on the first incremental update. The grepper applies three case-folding rules at once, so substring search misses matches its own highlighter accepts (**155 rows** for one search string) and only **17%** of Devanagari word-search hits are correct. Because acatalogue never deletes, an ingest error becomes permanent history, while an index error disappears at the next rebuild; that is why claim fidelity ranks first and search second. Next come first-class qualifiers, references and typed dates, checked against Wikidata's own 32 constraint types written as SQL; then a split between machine proposals and human decisions (**399 of 400** `exactMatch` crosswalks were accepted by an AI agent) and a bias audit measured against declared baselines, both before scaling multiplies unreviewed content; then updates from weekly dumps plus the EventStreams change feed, a multilingual embedding model run through ONNX and adopted only after it wins an evaluation that hides one language at a time from the index, and a particle layout computed once offline ("baked"), made accessible, and moved to a worker and WebGL2 before 10⁴ nodes. Motion and edge-bundling polish come last. Three choices remain open—the rule for turning a deprecated rank into an epistemic status, the embedding model and the bias baselines—because they are value judgments or unmeasured, and acatalogue's own tests must settle them. Implementation began while this report was written: by publication the search defects, the rank mapping and the error-body sealing were fixed, and statement import with GUIDs, qualifiers and per-subject supersession was under way.

## Forty-nine changes, ranked from silent loss to polish

The ranking follows four rules. **The record outranks the index**: acatalogue never deletes, so a claim ingested wrong or incomplete stays in its history and can only be superseded, whereas full-text and vector indexes are derived and a rebuild erases their mistakes. **Latent defects outrank the features that trigger them**: several bugs are harmless at 4,045 claims and one corpus but fire on the first qualified import, delta corpus, `maxlag` parameter or `VACUUM`, all four of which the scale roadmap introduces. **Governance outranks volume**, because scale multiplies whatever review process exists, and today the ledger's only actors are build commands while every accepted crosswalk names either an AI agent or the seed files as its reviewer (read-only query of [acatalogue.sqlite](../data/acatalogue.sqlite)). **Knowledge outranks presentation**, and within the visualization deterministic layout and WCAG Level A accessibility come before speed, with appearance last. Ranks are priorities, not a serial schedule: cheap items in later tiers, such as fetch compliance (4.1) or a pause control (6.2), can ship alongside Tier 1.

Nothing on the list rewrites acatalogue's foundations, because they already match best practice. **The SHA-512 exact-byte source table** with delete-blocking triggers is stronger than Wikidata's own reference hashes, which serve deduplication rather than integrity ([RDF Dump Format](https://www.mediawiki.org/wiki/Wikibase/Indexing/RDF_Dump_Format)), and it follows the trusty-URI principle that any change in content makes a new artifact ([Kuhn & Dumontier](https://pdfs.semanticscholar.org/74ce/57f3a4d62c53bbb2f89a02c6ee8f22531059.pdf)). **Never deleting claims** matches Wikidata's rule that even deprecated statements must stay verifiable ([Help:Ranking](https://www.wikidata.org/wiki/Help:Ranking)) and DBpedia's practice of still publishing the triples its checks filter out ([DBpedia](http://dev.dbpedia.org/Post-Processing)). The bitemporal columns need precision and bounds rather than a redesign, the hash-chained ledger needs external anchoring rather than replacement, and the epistemic vocabulary with its `perspective` field expresses contestation that Wikidata's three ranks cannot. **Git-tracked seeds plus sealed corpora should remain the system of record**—DoltLite is in beta and its files are not SQLite pages ([DoltLite](https://github.com/dolthub/doltlite)), and lakeFS moved to the Business Source License on 22 September 2026 ([lakeFS](https://lakefs.io/blog/lakefs-business-source-license/))—and vectors keyed by model ID already let a new embedding model sit beside LSA instead of silently replacing it ([semantic.py](https://github.com/virideanil/acatalogue/blob/68f970432492d017beed38af4908ccf3cd3d8185/acatalogue/semantic.py)).

**Status at publication.** Findings about acatalogue's own code and data describe commit [68f9704](https://github.com/virideanil/acatalogue/tree/68f970432492d017beed38af4908ccf3cd3d8185), the last commit before any fix, and the database built from it; code links are pinned there. Implementation began while this report was being written. Commit [986985c](https://github.com/virideanil/acatalogue/commit/986985c140ccfc9dec27d8a7d8d71e4d9d2cbb9b) completed 1.7, 1.8, 1.9 and 5.5 and the default in 1.4 (the 81 deprecated claims are now `attributed`), and began 1.1–1.3, 2.1–2.3, 2.6 and 5.6 with new claim columns, qualifier and reference tables, the SKOS integrity checks, a CJK character-pair index and NFC-normalized queries; the SKOS checks' first run found **82 alternative labels duplicating preferred labels and 8 `related` links restating the hierarchy**. Commit [3eea16a](https://github.com/virideanil/acatalogue/commit/3eea16a4fbcb6198b32ccb4064816e1d1f24733c) completed 1.6 and the gzip and `maxlag` parts of 4.1. A statement importer that fills the new columns and supersedes claims per subject (1.1–1.3 and 1.5) was in progress, uncommitted, at publication. Everything else remains open, including the P2241 rule in 1.4, hidden labels, calendars and date bounds, the constraint layer, all of Tier 3, and Tiers 4–7 beyond the parts named here.

## Tier 1: six boundaries quietly drop, relabel or miss data

This section describes the research snapshot; the status note above records which fixes have since landed. The first boundary is where Wikidata data enters. acatalogue imports claims from WDQS SPARQL result tables whose query flattens each statement to item, property, value and rank. As a result, **all 4,045 claims trace to three files of 0.5–1 MB** and carry **zero qualifiers, zero dates and zero literal values** (read-only query of [acatalogue.sqlite](../data/acatalogue.sqlite)). Wikidata's entity JSON holds far more. A check of Q4115189 on 25 September 2026 showed a statement GUID, hash-identified snaks and references, and entity-level `lastrevid` and `modified` fields ([EntityData Q4115189](https://www.wikidata.org/wiki/Special:EntityData/Q4115189.json); [Wikibase JSON](https://doc.wikimedia.org/Wikibase/master/php/docs_topics_json.html)).

Switching to entity JSON is safe only after the identity key changes, because `claim_identity` has no statement ID. Two statements with the same value but different qualifiers, such as the same office held for two separate terms, would collide, and `INSERT OR IGNORE` would drop the second without an error ([schema.sql](https://github.com/virideanil/acatalogue/blob/68f970432492d017beed38af4908ccf3cd3d8185/acatalogue/schema.sql); [wikidata.py](https://github.com/virideanil/acatalogue/blob/68f970432492d017beed38af4908ccf3cd3d8185/acatalogue/sources/wikidata.py)). Wikidata treats qualifiers as part of what makes a statement distinct; its single-value constraint, for example, lets "separator" qualifiers tell values apart ([Ferranti et al.](https://journals.sagepub.com/doi/full/10.3233/SW-243611)). The ledger shows 4,045 bindings producing 4,045 rows, so nothing has been lost yet. The hole opens with the first qualified import, and closing it deletes no data because only an index is rebuilt. How many of today's P31, P279 and P527 claims carry qualifiers in Wikidata is unmeasured; sampling 100 entity JSONs would size the gain.

The import boundary also flattens meaning, and the second boundary, from rank to epistemic status, over-reads it. Wikidata distinguishes a known value from **"unknown value"** (Ambrose Bierce has a date of death nobody knows) and from **"no value"** (a circle has no angle) ([Wikibase DataModel](https://www.mediawiki.org/wiki/Wikibase/DataModel)). acatalogue's CHECK constraint admits neither. Its importer also skips any value that is not a Q-id, which is how WDQS represents unknown values ([RDF Dump Format](https://www.mediawiki.org/wiki/Wikibase/Indexing/RDF_Dump_Format)). A fact that something exists and a fact that nothing exists both become silence.

Rank is over-read in the opposite direction. All **81 deprecated claims** are stored as `epistemic/superseded`, which the catalogue defines as "the source itself later withdrew or replaced it". But Wikidata deprecates both outdated knowledge and information "that was never correct, but was at some point thought to be" ([Help:Ranking](https://www.wikidata.org/wiki/Help:Ranking)). Its P2241 reasons separate "superseded by later scholarship" from "incorrect value", "conflation" and "typographical error" ([P2241](https://www.wikidata.org/wiki/Property:P2241)). acatalogue's own scheme requires every status other than `attributed` to name who judged it and by what rule ([epistemic.tsv](https://github.com/virideanil/acatalogue/blob/68f970432492d017beed38af4908ccf3cd3d8185/seed/schemes/epistemic.tsv)). The defensible default is therefore `attributed` with `rank='deprecated'`, upgraded only by a rule recorded in the ledger. That mapping from P2241 reasons to statuses is this report's proposal and has not been tested against real deprecated statements.

The third and fourth boundaries are one-line assumptions today that become silent corruption the week Tier 4 ships. After each import, every current claim from any other `wikidata-entities-*` corpus is marked superseded, on the assumption that each corpus restates everything still true ([wikidata.py](https://github.com/virideanil/acatalogue/blob/68f970432492d017beed38af4908ccf3cd3d8185/acatalogue/sources/wikidata.py)); a daily delta corpus built from EventStreams holds only the entities that changed ([EventStreams](https://wikitech.wikimedia.org/wiki/Event_Platform/EventStreams_HTTP_Service)), so **importing one would retire claims about every entity it never touched**. Separately, `fetch()` seals every HTTP 200 body without reading it, and its resume shortcut returns a stored item instead of fetching again ([fetch.py](https://github.com/virideanil/acatalogue/blob/68f970432492d017beed38af4908ccf3cd3d8185/acatalogue/fetch.py)). Wikidata reports replication lag as an HTTP 200 carrying the error code `maxlag` ([Manual:Maxlag](https://www.mediawiki.org/wiki/Manual:Maxlag_parameter)), so adopting the recommended `maxlag=5` parameter ([API:Etiquette](https://www.mediawiki.org/wiki/API:Etiquette)) without parsing error bodies would seal lag errors as source data and serve them forever.

The last two boundaries sit between the catalogue and its search indexes. The grepper applies SQLite's case folding to search strings of three or more characters, Python's `casefold` to shorter ones, and `re.IGNORECASE` to highlights and `(?i)` regexes ([grep.py](https://github.com/virideanil/acatalogue/blob/68f970432492d017beed38af4908ccf3cd3d8185/acatalogue/grep.py)). SQLite folds case by Unicode 6.1 rules and leaves **402 of Python's 1,427 multi-member case-equivalence classes** split, including Turkish I, İ and ı, Cherokee, Georgian Mtavruli and Adlam. So `"istanbul"` misses `İstanbul`, and one search string containing a dotless ı missed **155 rows** that the grepper's own highlighter treats as hits ([Exp A](../research_notes/Improving%20the%20acatalogue%20knowledge%20base/prototypes/regex_fts_exp1.py); [Exp B](../research_notes/Improving%20the%20acatalogue%20knowledge%20base/prototypes/regex_fts_exp2.py)).

The fix is to pick one rule, Python's `re.IGNORECASE` equivalence for literal characters. Regex search and highlighting already use it, and it maps each character to exactly one character, whereas `casefold` turns ß into "ss" and breaks highlight offsets. A prototype that stores this folded key in a `trigram case_sensitive 1` index showed **zero consistency violations and zero false negatives** ([Exp C](../research_notes/Improving%20the%20acatalogue%20knowledge%20base/prototypes/regex_fts_exp3.py)). The price is that `arı` matches `ARI`, merging Turkish ı and i. That is acceptable for grep, and a reason to keep the folding optional for ranked word search.

Word search needs one more, nearly free, fix. With its default categories, the unicode61 tokenizer treats combining marks as separators, so हिन्दी splits into ह, न and द. Adding `M*` raises Devanagari precision from **0.171 to 1.000** ([Exp D](../research_notes/Improving%20the%20acatalogue%20knowledge%20base/prototypes/regex_fts_exp4.py); [FTS5](https://sqlite.org/fts5.html)). Finally, `label`'s composite primary key leaves its rowid without a stable alias, so `VACUUM` can renumber rows underneath both label indexes, which point into the table by rowid ([VACUUM](https://sqlite.org/lang_vacuum.html)). They are aligned today; an `INTEGER PRIMARY KEY` plus `PRAGMA integrity_check` keeps them that way.

## Tier 2: fidelity and validation turn claims into checkable facts

Tier 2 makes the claim table say what its sources say, then checks it. A Wikidata statement maps one-to-one onto a claim row with child tables, and so does an RDF 1.2 reifier. The relational store therefore loses nothing, and RDF can be an export format, which is prudent while RDF 1.2 is still a Candidate Recommendation ([RDF 1.2](https://www.w3.org/TR/rdf12-concepts/)). The layout is also fast. In one benchmark, PostgreSQL with keyed Statement and Qualifier tables was "often an order of magnitude faster" than the RDF stores and Neo4j it was compared with. Only 11 of 94 example queries touched qualifiers, so a few plain indexes cover the common query paths ([Hernández et al.](https://aidanhogan.com/docs/wikidata-sparql-relational-graph.pdf)).

References add the second level of attribution that an attributed catalogue promises: today acatalogue can prove what Wikidata said, but not what Wikidata cites. That gap matters because only **68–73% of Wikidata statements carry any reference**, and a referencing-quality study scored them **0.58 out of 1** ([Beghaeiraveri et al.](https://researchportal.hw.ac.uk/files/53252708/Reference_Statistics_in_Wikidata_Topical_Subsets_corrected_version.pdf); [RQSS](https://www.semantic-web-journal.net/content/rqss-referencing-quality-scoring-system-wikidata)). Statements supported only by "imported from Wikimedia project" do not count as sourced ([Help:Sources](https://www.wikidata.org/wiki/Help:Sources)). A per-claim `is_sourced` flag makes that visible.

Typed dates prevent a class of wrong answers before the first date arrives. Concept date spans are already parsed to integer years, with year 0 standing for 1 BCE ([compendium.py](https://github.com/virideanil/acatalogue/blob/68f970432492d017beed38af4908ccf3cd3d8185/acatalogue/compendium.py)), but claim `valid_from` and `valid_to` are free text, and **signed ISO strings sort BCE years backwards**. Wikidata's date format adds three traps: each date carries a precision code, from a billion years (0) to a day (11), and a calendar (Julian before 1583); the JSON export writes 1 BCE as −0001 while the RDF export and acatalogue use year 0; and a Wikidata century runs 1801–1900, which EDTF's `18XX` (1800–1899) misstates ([Help:Dates](https://www.wikidata.org/wiki/Help:Dates); [EDTF](https://www.loc.gov/standards/datetime/)). Storing the verbatim value with its precision, calendar and integer day bounds turns "what was true in year X" into an integer comparison, and lets date-difference checks flag a violation only when even the most favourable reading of both dates fails.

Validation should run on Wikidata's own terms. Wikidata's quality work rests on **32 advisory constraint types and more than 72,000 constraint definitions**, each with a mandatory or suggestion status and explicit exceptions. SHACL-Core, the W3C shape language, cannot fully express six of the types, and existing SHACL validators could not handle the full set, while SPARQL expresses all 32 ([Ferranti et al.](https://journals.sagepub.com/doi/full/10.3233/SW-243611); [constraints portal](https://www.wikidata.org/wiki/Help:Property_constraints_portal)). SQL with recursive queries, arithmetic and a registered `regexp` function is at least as expressive. Each constraint type can therefore become a versioned SQL template run over constraints imported as sourced data. Severity must be kept, because violation rates run **0.03–0.08%** for mandatory constraints but reach **20%** for suggested ones ([Shenoy et al.](https://arxiv.org/abs/2107.00156)).

One design point is specific to acatalogue: it holds 2,705 items, not all of Wikidata. A check that a claim's value item has the right type must return `unknown`, not `violation`, when that item was never fetched. Ferranti et al. met the same problem on Wikidata's own incomplete dump. YAGO 4.5 shows what else to check: it removed 57 loops, 40,000 redundant links and 1.3 million empty classes from Wikidata's taxonomy. It also shows what not to copy, since it deleted roughly 6% of facts that failed its domain and range checks ([YAGO 4.5](https://arxiv.org/abs/2308.11884)). acatalogue should flag the same defects and serve a clean view, as DBpedia serves filtered triples "as errors, but … still provided" ([DBpedia](http://dev.dbpedia.org/Post-Processing)). SHACL, whose version 1.2 is still a Working Draft, belongs in exports ([SHACL 1.2](https://www.w3.org/TR/shacl12-core/)).

The curated concept layer gets the same discipline through SKOS. Its integrity conditions become tests: preferred, alternative and hidden labels must be disjoint; each concept has one preferred label per language tag; `related` must not coincide with any broader path; and `exactMatch` must not coincide with `broadMatch`. SKOS says nothing about versioning, and the `owl:deprecated` plus `dct:isReplacedBy` practice that Skosmos reads fills that gap ([SKOS Reference](https://www.w3.org/TR/skos-reference/); [Skosmos](https://github.com/NatLibFi/Skosmos/wiki/Data-Model)).

Tamper evidence closes the tier rather than opening it, because a per-claim content hash must cover qualifiers, reference hashes and the source pointer, or it would change on every richer re-import. Once that hash exists, three proven patterns apply: identifiers that carry their own hash, used by more than 10 million nanopublications ([Kuhn et al.](https://arxiv.org/abs/1809.06532)); Merkle logs, which give O(log n) proofs that an item is included and that the log has only been appended to ([RFC 9162](https://www.rfc-editor.org/rfc/rfc9162.html)); and hash-based identifiers standardized by ISO, as Software Heritage's SWHID now is ([SWHID](https://www.iso.org/standard/89985.html)). **Anchoring the ledger head outside the database matters most**, because a hash chain proves order but not that its head was never rewritten.

## Tier 3: bias becomes auditable only with baselines and recorded voices

Knowledge-organization history is blunt about what keeps a classification scheme alive. Success is "related less to their theoretical and research based qualities than to the strength of support for maintaining systems". Colon Classification's 7th edition was discarded by its own profession, and the Bliss scheme (BC2) had "no formal provision" for updates ([ISKO: Colon Classification](https://www.isko.org/cyclo/colon_classification); [ISKO: BC2](https://www.isko.org/cyclo/bc2)). Maintenance process is acatalogue's gap. No review or proposal records exist, and **399 of its 400 `exactMatch` crosswalks** were accepted by an AI agent ([acat-wikidata.tsv](https://github.com/virideanil/acatalogue/blob/68f970432492d017beed38af4908ccf3cd3d8185/seed/crosswalk/acat-wikidata.tsv)). Because `exactMatch` is transitive, one wrong link propagates through the UDC, DDC, LCC and Wikidata chains ([SKOS Reference](https://www.w3.org/TR/skos-reference/)).

Mature projects keep the machine's guess and the person's decision in separate states. Mix'n'match distinguishes "preliminarily matched" from "fully matched", and the Reconciliation API separates a candidate's `score` from its `match` flag. OBO ontologies require a ticket, automated checks and a second reviewer for every change ([Mix'n'match](https://meta.wikimedia.org/wiki/Mix'n'match/Manual); [Reconciliation API](https://reconciliation-api.github.io/specs/1.0-draft/); [ODK](https://obofoundry.org/COB/odk-workflows/EditorsWorkflow/)). Comment windows guard against both haste and capture. LCSH normally allows three weeks, but its March 2025 renaming of the Gulf of Mexico and Denali, which deferred to a US government naming board, allowed **under 24 hours** ([CCC Libraries](https://ccclibraries.org/blogs/deiaa_workgroup/blog/library-of-congress-changes-gulf-of-mexico-and-mount-denali-subject-headings); [ACRLog](https://acrlog.org/2025/03/28/anticipatory-obedience-at-the-library-of-congress/)).

Bias measurement has to be built in-house, and built carefully. The dedicated gender dashboards are stale or dead: Humaniki's newest snapshot dates from 23 June 2025, and Denelezh and WHGI no longer respond ([Humaniki API](https://humaniki.wmcloud.org/api/v1/available_snapshots/)). Headline numbers swing with the denominator. In that snapshot, women are **19.03%** of Wikidata humans who have a Wikipedia article but **26.35%** of all Wikidata humans ([Humaniki](https://humaniki.wmcloud.org/api/v1/gender/gap/latest/gte_one_sitelink/properties)). Coverage baselines also inherit the bias they measure, since women's biographies are more often nominated for deletion ([Tripodi](https://doi.org/10.1177/14614448211023772)). Wikipedia's distribution is therefore a reference, never a target. A model of expected coverage helps separate structural causes from editorial ones: simple Internet-access factors explain **71% of the variance** in geotagged Wikipedia content ([Graham et al.](https://ora.ox.ac.uk/objects/uuid:7d4449ab-59a9-468a-826e-e0dc7a7d3975/files/m3ececf4e6253825bb1a7d7e90a65abb8)).

The audit design follows the Wikimedia Knowledge Gaps Index ([KGI](https://meta.wikimedia.org/wiki/Research:Knowledge_Gaps_Index/Measurement)). For each group it reports the share with a log2 representation ratio and a Wilson confidence interval ([Wilson](https://doi.org/10.1080/01621459.1927.10502953)); a bounded Jensen–Shannon divergence from the baseline ([Lin](https://doi.org/10.1109/18.61115)) with bootstrap intervals ([Efron](https://doi.org/10.1214/aos/1176344552)) and a comparison against pure sampling noise, because entropy estimates are biased at acatalogue's sample size of about 600 ([Paninski](https://doi.org/10.1162/089976603321780272)); and normalized entropy and the Gini coefficient. Each is measured against several declared baselines and **never folded into one score**. No standard says which baseline suits a topical scheme, so that choice is a value judgment that must be documented, and Wilson intervals over concepts split across several regions are only approximate.

A classification also carries biases that coverage counts cannot see. OCLC itself acknowledges "Christian bias" in the Dewey 200s and offers an optional rearrangement modelled on UDC's 2000 revision, which ranks religions equally ([OCLC](https://www.oclc.org/en/dewey/resources/religion.html); [UDC](https://udcc.org/index.php/site/page?view=major_revisions)); a "no Other X" rule cannot detect that pattern, but comparing siblings' subtree size, scope-note length, alternative labels and mappings can. Residual categories cannot be abolished, only distributed and watched, as the ICD does with "not elsewhere classified" ([Bowker & Star](https://hcommons.org/app/uploads/sites/1001532/2020/03/Bowker-1999-Sorting-Things-Out-Classification-and-Its-Consequences.pdf)). Epistemic status must apply symmetrically under the CARE principles' rule against deficit framing: if Indigenous cosmologies are "held within a tradition", so is every other tradition's doctrine ([CARE](https://www.gida-global.org/s/CAREPrinciples_OnePagersFINAL_Oct_17_2019.pdf)). Attention signals need correcting too, because one bot, Lsjbot, created roughly **9.5 million articles**, two-thirds of them in Cebuano, inflating counts of Wikipedia editions per item ([Lsjbot](https://en.wikipedia.org/wiki/Lsjbot)), and **11 languages hold almost half** of Wikidata's labels ([Kaffee et al.](https://www.opensym.org/wp-content/uploads/2017/08/a14-kaffee.pdf)). Some dimensions cannot be measured honestly at all—most Wikipedia biographies lack ethnicity data ([Mandiberg](https://doi.org/10.1215/01642472-10174954))—and the audit should say so rather than print a number.

Plurality and authority are the constructive half. Disputed names become several labels, each tagged with the authority that uses it and a date, and a published rule picks the display label. A government-directed rename then adds a label instead of replacing one. Each concept also shows its UDC, DDC, LCC, Propaedia and Wikidata placements beside acatalogue's own, which is what a catalogue that can never be finally "corrected" owes its users ([Drabinski](https://doi.org/10.1086/669547)).

For peoples, languages and traditions, self-names become preferred labels. Precedents are the Māori Subject Headings, built through hui (community meeting) consultation, and the X̱wi7x̱wa Library's names list, maintained "to best reflect the preferences of First Nations" ([Te Rōpū Whakahau](https://trw.org.nz/professional-development/nga-upoko-tukutuku-maori-subject-headings/); [X̱wi7x̱wa](https://xwi7xwa.library.ubc.ca/collections/indigenous-knowledge-organization/)). A `custodian` field and a Local Contexts-style Notice ("described externally, not community-reviewed") implement CARE's Authority to Control principle until a community applies its own Label ([Carroll et al.](https://doi.org/10.5334/dsj-2020-043); [Local Contexts](https://localcontexts.org/labels/about-the-labels/)).

The facets need refinement more than reinvention. Place and time recur in every tradition surveyed, and Colon Classification's later editions show why each facet needs its own marker. Modelling the 13 domains as an unordered `skos:Collection` states formally that they are not ranked ([ISKO: facet analysis](https://www.isko.org/cyclo/facet_analysis); [UDC tables](https://udcc.org/index.php/site/page?view=about_structure)). Whether acatalogue can recruit community custodians is an organizational question the literature cannot answer.

## Tiers 4–5: dumps, streams and a measured embedding model carry the scale

### 123 million items arrive through dumps and streams, not APIs

Wikidata listed **123,431,511 items** on 25 September 2026 and held about 1.65 billion statements in early 2025 ([Wikidata:Statistics](https://www.wikidata.org/wiki/Wikidata:Statistics); [Wikipedia](https://en.wikipedia.org/wiki/Wikidata)). The APIs cannot carry that load. The 2026 limits allow 10 requests a minute for unidentified clients, 200 for identified ones and 2,000 for established editors ([Rate limits](https://www.mediawiki.org/wiki/Wikimedia_APIs/Rate_limits)). Fetching ~76 million entities 50 at a time would take about **5.3 days** of nonstop calls, against Wikimedia's explicit advice that substantial needs "should be using dumps" ([Rate limits FAQ](https://www.mediawiki.org/wiki/Wikimedia_APIs/Rate_limits/FAQ)).

The sanctioned pattern maps cleanly onto sealed corpora: a baseline from the weekly **156.3 GB** JSON dump, in which every entity line carries `lastrevid` and `modified` ([dump listing](https://dumps.wikimedia.org/wikidatawiki/entities/)); changes from EventStreams, which can replay 7–31 days of events but **silently restarts at the latest event** if asked for anything older ([EventStreams spec](https://stream.wikimedia.org/?spec)); exact revisions from `EntityData?revision=N` ([Data access](https://www.wikidata.org/wiki/Wikidata:Data_access)); and a weekly comparison of `lastrevid` against the next dump to catch missed events. In May 2025 WDQS was split into main and scholarly graphs because it had passed 16 billion triples and was growing by a billion a year, one more reason to run graph-wide checks on a local QLever index, which builds in about four hours on a 64 GB machine, rather than on the public endpoint ([WDQS split](https://www.wikidata.org/wiki/Wikidata:SPARQL_query_service/WDQS_graph_split); [QLever](https://www.wikidata.org/wiki/Wikidata:Scaling_Wikidata/Benchmarking/QLever)).

SQLite's size limit is not the constraint; it allows 281 TB per database. What argues for incremental builds, written to a temporary file, swapped in atomically and opened read-only, is its single writer, the risk that WAL fails on transactions above a gigabyte, and a WAL-reset bug fixed only in 3.51.3 while the local runtime is 3.45.1 ([SQLite limits](https://www.sqlite.org/limits.html); [WAL](https://www.sqlite.org/wal.html)). Article text and topics follow the same dump-first logic, with licensing duties attached: the CirrusSearch dumps moved in January 2026, and CC BY-SA text must carry attribution, a licence link and a note that splitting it into passages modified it ([cirrussearch notice](https://dumps.wikimedia.org/other/cirrussearch/DEPRECATED.txt); [Reusing Wikipedia content](https://en.wikipedia.org/wiki/Wikipedia:Reusing_Wikipedia_content)). OpenAlex's refusal was simply the $0.10 daily budget for requests without a key, and its entire topic tree costs about half a cent with a free key ([OpenAlex costs](https://help.openalex.org/access/example-costs/)). Several operational facts remain unverified: whether `EntityData` requests count against the 2026 limits, how unauthenticated clients are identified for rate limiting, whether the new CirrusSearch shards keep the `opening_text` field, and what the qualifier and reference tables would cost in storage at 1.65 billion statements.

### Semantic search must first win a leave-one-language-out test

Today's semantic layer is LSA (latent semantic analysis) in 48 dimensions over about 600 English concept texts. That leaves 121,717 labels in 489 languages outside semantic reach, which is a neutrality gap as much as a quality gap ([semantic.py](https://github.com/virideanil/acatalogue/blob/68f970432492d017beed38af4908ccf3cd3d8185/acatalogue/semantic.py)). No public benchmark resembles this task, so the evaluation harness comes first. It generates known-item queries from each concept's labels in one language while hiding that language from the index, and adds 50–100 graded descriptive queries. It reports scores per language and for the worst language, with bootstrap intervals and randomization tests, because Wilcoxon and sign tests "should be discontinued" ([Smucker et al.](https://dl.acm.org/doi/10.1145/1321440.1321528)) and even significance on 50 topics can mislead ([Voorhees](https://dl.acm.org/doi/10.1145/1571941.1572138)).

For this task, the leaderboards read upside down. Short cross-lingual label lookup resembles matching translated sentences (bitext mining) more than passage retrieval. On bitext mining, **multilingual-e5-large-instruct scores 80.13 against Qwen3-Embedding-0.6B's 72.22**, although Qwen3 leads on retrieval, 64.64 to 57.12 ([Qwen3 card](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B)). Granite-Embedding-311M-R2 is the natural challenger: Apache-2.0 licensed, with a 32K-token context, and it can be truncated to 256 dimensions at a cost of 0.4 points. But its 65.2 comes from IBM's own aggregate and cannot be ranked against leaderboard columns ([Granite R2](https://huggingface.co/ibm-granite/granite-embedding-311m-multilingual-r2)). jina v3 and v5 are licensed CC BY-NC and EmbeddingGemma is gated, which rules both out for an open catalogue ([jina](https://huggingface.co/api/models/jinaai/jina-embeddings-v5-text-small); [EmbeddingGemma](https://huggingface.co/api/models/google/embeddinggemma-300m)). ONNX Runtime plus `tokenizers` runs either candidate from about 25 MB of packages, instead of torch's 127 MB ([onnxruntime](https://pypi.org/pypi/onnxruntime/json); [torch](https://pypi.org/pypi/torch/json)).

The rest of the search stack stays small. Exact numpy search over vectors stored as SQLite BLOBs measured about **9 ms per query at 100,000 vectors of 768 dimensions** on a 4-vCPU container ([session measurement](../research_notes/Improving%20the%20acatalogue%20knowledge%20base/semantic_hybrid_search.md)), so neither an approximate index nor an extension that macOS's bundled SQLite cannot load ([sqlite-vec](https://alexgarcia.xyz/sqlite-vec/python.html)) is justified below about a million vectors. Results are merged by reciprocal rank fusion at k=60, which its authors found "near-optimal, but … not critical" ([RRF](https://plg.uwaterloo.ca/~gvcormac/cormacksigir09-rrf.pdf)); hybrid search raised MIRACL nDCG@10 to 0.581 from 0.388 and 0.421 for either method alone ([Pyserini](https://castorini.github.io/pyserini/2cr/miracl.html)), yet with a very strong dense model fusion was best on only one of eight BEIR datasets ([scrydb](https://arxiv.org/html/2608.24060)), so dense-only and lexical-only runs must be reported beside the fused one. The keyword engine gains most from a Cox-style regex prefilter, which had **no false negatives on 400 random patterns**, could prefilter 348 of them against 209 for the current rule and cut scan time from 11.53 s to 0.10 s ([Exp C](../research_notes/Improving%20the%20acatalogue%20knowledge%20base/prototypes/regex_fts_exp3.py); [Cox](https://swtch.com/~rsc/regexp/regexp4.html)), and from CJK character-pair (bigram) shadow columns, which raised recall for two-character words from 0.370 to 1.000 ([Exp D](../research_notes/Improving%20the%20acatalogue%20knowledge%20base/prototypes/regex_fts_exp4.py)). Thai word segmentation remains unsolved without a dependency beyond the Python standard library.

## Tiers 6–7: a baked, accessible layout unlocks the million-particle map

The particle map's first problem is truth, not speed. Its physics was measured at **10.5 ms per step at 10,000 particles, 106 ms at 100,000 and 1.4 s at a million**, against an 8.3 ms budget at its 120 Hz step rate. Live physics for the whole graph therefore ends near 10⁴ particles ([benchmark](../viz/bench/bh_bench.mjs); [physics.ts](https://github.com/virideanil/acatalogue/blob/68f970432492d017beed38af4908ccf3cd3d8185/viz/src/physics.ts)). The same benchmarks showed that the 65-unit force cutoff means the Barnes-Hut far-field approximation is never used: forces match brute force to 10⁻¹³. A sorted cell list (a grid of neighbour cells) computes identical forces 2.0–2.6 times faster ([accuracy](../viz/bench/grid_bench.mjs); [cell list](../viz/bench/grid2_bench.mjs)).

Beyond speed, JavaScript's `Math` functions and WebGPU shader arithmetic (WGSL) do not give bit-identical results across browsers and devices ([MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Math); [WGSL](https://www.w3.org/TR/WGSL/)), so the layout a user sees depends on their browser. Baking the layout offline fixes both problems. Run the same compiled `physics.js` in Node from a seeded start for a fixed number of steps, store the result in the `layout` table, and let the browser simulate only disturbances such as drags. The seed already exists: `semantic.py` emits a PCA projection of the concept vectors as `xy`, which the browser parses and then ignores ([data.ts](https://github.com/virideanil/acatalogue/blob/68f970432492d017beed38af4908ccf3cd3d8185/viz/src/data.ts)). A meaningful starting layout like this is what preserves global structure in projections ([Kobak & Linderman](https://www.nature.com/articles/s41587-020-00809-z)). Used as anchor springs much weaker than the hierarchy springs, the semantic positions order particles locally while the ring and hierarchy still decide the global shape, so motion remains physics.

Two accessibility gaps are correctness requirements. **WCAG 2.2.2, at Level A, requires a way to pause** automatic motion that lasts more than five seconds alongside other content ([WCAG 2.2.2](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)); how long today's 966-node graph takes to settle was not measured, but at 10⁵ nodes settling will exceed five seconds unless the layout is baked, and no pause control exists. The data also needs a non-visual route: an accessible tree of the hierarchy following the ARIA Authoring Practices tree pattern, loaded lazily with `aria-level`, `aria-setsize` and `aria-posinset` so it scales to a million nodes, with each focused node's neighbours offered as navigable lists ([APG Tree View](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/); [Data Navigator](https://arxiv.org/abs/2308.08475)).

Speed work then follows the thresholds. Canvas 2D is enough at today's 966 nodes and 3,798 edges. But at 68,000 edges, Cytoscape's Canvas renderer fell to 3 fps where its WebGL renderer managed 10 ([Cytoscape](https://blog.js.cytoscape.org/2025/01/13/webgl-preview/)), and WebGL2 instanced drawing sustains about a million items at 60 fps ([deck.gl](https://deck.gl/docs/developer-guide/performance)). A hand-written WebGL2 renderer with three shader programs should therefore land before about 2×10⁴ edges. Existing libraries (sigma.js, cosmos.gl, deck.gl) would each replace acatalogue's force law and camera.

WebGPU stays optional. A GPU layout built on a bottom-up quadtree processed 94,893 nodes and 6.6 million edges at 5.48 ms per iteration ([Dyken et al.](https://par.nsf.gov/servlets/purl/10610241)). But WebGPU is missing on most Linux GPUs, and deck.gl 9.4 still calls its WebGPU path experimental ([gpuweb](https://github.com/gpuweb/gpuweb/wiki/Implementation-Status); [deck.gl](https://deck.gl/docs/whats-new)).

A million particles, fitted to the screen, would pack about 1.3 particles into each CSS pixel. Detail must therefore come from the hierarchy: domains, then concepts, then entities, with aggregates drawn as real particles carrying their members' mass. Labels should come from precomputed zoom ranges that follow Been et al.'s rule that nothing pops in or out during navigation ([Been et al.](https://cs.nyu.edu/~visual/home/pub/infovis06.pdf)). The JSON payload, 64.8 bytes per element today, would reach about 324 MB at that scale, against about 56 MB as binary tiles ([graph.json](../viz/data/graph.json)).

Only then do the cosmetic items earn a place: an exact critically damped camera spring, which restores the drag spring's stated stiffness where the current integrator (semi-implicit Euler) slows it by 16% ([Holden](https://theorangeduck.com/page/spring-roll-call); [benchmark](../viz/bench/spring_check.mjs)), and bundling of the aggregated domain edges. No rendering threshold was measured on acatalogue's own renderer, because no browser was available; a Playwright benchmark is the next measurement.

## Conclusion

acatalogue's correctness work and its scale work are one project, done in order. At the research snapshot, each scale feature on the roadmap was also the trigger for a latent defect: the first qualified import would collide on the identity key, the first delta corpus would trip the corpus-wide supersession rule, the first `maxlag` parameter would seal an error as data, a `VACUUM` on a larger file could desynchronize the label indexes, and the first 10⁵-node graph would turn an animation that cannot be paused into a Level A failure. The implementation has followed that coupling so far: the error-body check shipped in the same commit that added `maxlag`, the rowid hazard was closed before anything vacuums the catalogue, and per-subject supersession is being written alongside the statement importer that would have tripped the old rule. "Correctness first" is therefore a precondition for growth, not caution, and a useful discipline is to require each Tier 4–6 change to name the Tier 1–2 fix it depends on.

Bias exposure, meanwhile, turns out to be provenance applied to judgments. acatalogue already hashes every byte it ingests. The classification literature, from Bowker and Star to CARE, asks for the same discipline applied to decisions: who accepted each mapping, against which baseline, as of which snapshot, and on whose authority a name is displayed. Across all six research areas, the recurring design move is the honest unknown: `unknown` outcomes for items never fetched, ethnicity declared unmeasurable, languages outside a model's coverage flagged rather than claimed, GPU positions marked as presentation only, and the existing audit caveat that "not stated is not disagrees". The remaining questions are empirical and local: how many current claims carry qualifiers in Wikidata, which embedding model wins acatalogue's own leave-one-language-out test, and where its renderer actually crosses its frame-rate thresholds.
